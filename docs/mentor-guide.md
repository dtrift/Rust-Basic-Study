# Памятка наставнику: как ревьюить ДЗ

## Общие принципы

1. **Сначала найди, что похвалить.** Буквально: первое сообщение в PR — что получилось хорошо.
2. **Максимум 3 замечания за один проход.** Остальное подождёт следующей итерации — иначе подросток перегорит.
3. **Не коммить за подростка.** Можно показать фрагмент кода в комментарии, но кнопки merge и правки — его руки.
4. **Вопрос важнее решения.** «Что случится с hero, если его передать в функцию по значению?» работает лучше готового ответа.
5. **30-минутное правило.** Если он сидит на одной ошибке компиляции больше 30 минут — дай решение прямо, с разбором почему.
6. **CI — первый ревьюер.** Красный чек = PR не готов к чтению, верни с комментарием «сначала зелёный CI».

## Порядок ревью одного PR

1. Открой PR, проверь чеки CI (build / test / fmt).
2. Запусти ветку локально: `git switch main && git pull`, потом `git switch hw-NN-... && cargo run`.
   Пройди сцену из раздела «Самопроверка» задания.
3. Прочитай diff целиком. Прогонись глазами по пунктам «Задачи» задания — всё ли сделано.
4. Комментарии: похвала → до 3 замечаний → вердикт (Approved / Request changes / Комментарий без блокировки).

## Критерии приёмки по блокам курса

| Блок         | Уроки | Минимум для «принято»                                           |
| ------------ | ----- | --------------------------------------------------------------- |
| Основы       | 1–6   | Игра запускается, есть карточка героя и рабочий бой с монстром  |
| Владение     | 7–10  | Нет лишних clone(); функции принимают ссылки осознанно          |
| Структуры    | 12–14 | Логика в методах, enum + match вместо цепочек if                |
| Ошибки       | 15–18 | Нет unwrap() вне тестов, у ошибок понятные пользователю тексты  |
| Генерики     | 19–24 | Трейты и генерики применены там, где реально повторялся код     |
| Коллекции    | 25–28 | Мир на HashMap, конвейеры итераторов вместо индексных циклов    |
| Куча, потоки | 30–35 | Потоки останавливаются (join), нет гонок, мьютексы без дедлоков |
| Финал        | 37–41 | Проект разбит на модули, README и релиз готовы                  |

## Типичные ошибки новичка в Rust (по темам)

- **Владение (7–8):** clone() на каждый чих; попытка использовать переменную после передачи
  в функцию; два `&mut` на одно и то же. Спроси: «кому сейчас принадлежит hero?»
- **Строки (10):** срез по не-границе UTF-8 (`&s[..2]` на русском тексте) — покажи
  `s.chars().count()` и `char_indices()`.
- **Option/Result (15–18):** unwrap() вместо обработки; потерянный `?`; сообщение об ошибке
  из debug-вывода (`{:?}`) вместо человеческого текста.
- **Генерики/трейты (19–24):** генерик «на всякий случай» без второго применения —
  это нормально как упражнение, но обсуди, где он реально нужен.
- **Потоки (31–34):** забытый `join()` (программа завершилась раньше потока); мьютекс,
  захваченный дважды в одном потоке (дедлок); передача `&mut Game` в поток — предложи
  спросить у компилятора `Send`/`Sync`.
- **Макросы (39):** слишком сложные правила. Достаточно простого `log!`.

## Полезные ссылки для ответов на вопросы

- `rustup doc` — документация офлайн.
- `rustc --explain E0382` (и любой код ошибки) — человеческое объяснение ошибки компилятора.
- Книга «The Rust Programming Language» на русском: https://doc.rust-lang.ru/stable/rust-by-example/
  и https://rust-lang-ru.github.io/rust-book-2019/ (перевод книги).

## Если подросток буксует

- Попроси объяснить своими словами, что должна делать функция — обычно дальше он чинит сам.
- Предложи удалить спорный кусок и написать заново маленькими шагами.
- Напомни: красный компилятор — это нормально, половина времени даже опытных растовцев.
