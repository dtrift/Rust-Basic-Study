# ДЗ 19. Обобщённое программирование. Статический полиморфизм

- **Урок:** 19. Обобщённое программирование. Статический полиморфизм
- **Ветка:** `hw-19-generics`
- **Время:** примерно 1.5 часа

> Перед стартом: `git switch main`, `git pull`, `git switch -c hw-19-generics`.

## Цель

Написать функции и структуру, которые работают с любым подходящим типом:
одна `largest` для чего угодно сравнимого, сумка, в которую можно класть и предметы,
и зелья, и заклинания.

## Легенда

У героя уже есть сумка для предметов. Но в той же игре хочется носить свитки,
зелья и трофеи — а заводить `ScrollBag`, `PotionBag`, `TrophyBag` скучно. Одна сумка
на всё — и компилятор сам проверит, что в неё не положат слона.

## Задачи

- [ ] Функция `largest<T: PartialOrd>(list: &[T]) -> &T` — самая большая сумка не нужна,
      нужен самый тяжёлый предмет: `heaviest(items: &[Item]) -> &Item` сначала напиши
      конкретно, потом обобщи до `largest` и вызови для `&[u32]`, `&[&str]` и `&[Item]`.
- [ ] Структура `Bag<T> { items: Vec<T>, capacity: usize }` с методами:
      `Bag::new(capacity)`, `put(&mut self, item: T) -> bool` (false, если нет места),
      `is_full(&self)`, `len(&self)`.
- [ ] Замени `Vec<Item>` в герое на `Bag<Item>`. Проверь, что магазин и подбор
      предметов работают через `put`/проверки.
- [ ] Заведи второй тип содержимого: `enum Potion { Heal(u32), Strength(u32) }` —
      сделай `Bag<Potion>` у торговца и положи туда 3 зелья. Убедись: положить `Item`
      в сумку зелий не даёт сам компилятор (напиши такой вызов и посмотри на ошибку —
      потом убери).
- [ ] Функция `find_by<T, F: Fn(&T) -> bool>(list: &[T], predicate: F) -> Option<&T>` —
      найди ею самый тяжёлый предмет по весу > N и любое зелье лечения.
- [ ] * Звёздочка: метод `Bag::swap_with(&mut self, other: &mut Bag<T>)` — обменять
      содержимое двух сумок одного типа.

## Самопроверка

- `largest` вызывается для трёх разных типов без дублирования кода.
- В `Bag<Item>` и `Bag<Potion>` кладётся соответствующее; попытка перепутать не компилируется.
- `cargo test`: тесты на `put` при полной сумке и на `find_by`.

## Подсказки

- `T: PartialOrd` — «тип, который умеет сравниваться», поэтому `largest` работает.
- Обобщения в Rust — compile-time: для каждого типа компилятор порождает свою версию
  функции (поэтому «статический» полиморфизм).
- `F: Fn(&T) -> bool` — параметр-замыкание или функция, что угодно вызываемое.
