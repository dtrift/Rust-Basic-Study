# ДЗ 26. Коллекции. Итераторы

- **Урок:** 26. Коллекции. Итераторы
- **Ветка:** `hw-26-iterators`
- **Время:** примерно 1.5 часа

> Перед стартом: `git switch main`, `git pull`, `git switch -c hw-26-iterators`.

## Цель

Перестать писать циклы руками: конвейеры `iter().filter().map().collect()`,
агрегаты `sum`/`max_by_key` и понимание ленивости итераторов.

## Легенда

Экран героя захламлён циклами: список предметов, суммарный вес, самый тяжёлый,
краткая сводка. Каждый цикл — три строчки шума. На итераторах каждая сводка —
одна строка, и читается как задание: «возьми предметы, отфильтруй тяжёлые, собери имена».

## Задачи

- [ ] Список предметов сумки одной строкой: `hero.bag.items.iter().map(|i| i.name.as_str()).collect::<Vec<_>>().join(", ")`.
- [ ] Суммарный вес: `iter().map(|i| i.weight).sum::<u32>()` — печать «Сумка: 5 предметов, 34 веса».
- [ ] Самый тяжёлый предмет: `iter().max_by_key(|i| i.weight)` — `Option<&Item>`,
      обработай пустую сумку.
- [ ] Фильтр: имена всех предметов тяжелее N: `iter().filter(...).map(...).collect::<Vec<_>>()`.
- [ ] Перепиши на итераторы три любых своих цикла в коде (поиск выхода, печать существ,
      подсчёт живых монстров — где найдёшь). Каждый переписанный — пометь комментарием
      «было/стало» (старую версию оставь закомментированной рядом — наставнику интересно).
- [ ] Эксперимент с ленивостью: `let it = hero.bag.items.iter().filter(|i| i.weight > 5);`
      напечатай счётчик `it.count()`; потом закомментируй `count()` и убедись, что
      ничего не напечаталось и не «сделалось» — итератор ждёт. Ответь в комментарии,
      что «толкает» конвейер к выполнению.
- [ ] * Звёздочка: `chain` — сцепи предметы героя и товары торговца в один список
      «всё, что можно купить или найти».

## Самопроверка

- Сводка сумки печатается конвейерами: 4 разных запроса, 0 явных циклов.
- Комментарий-объяснение ленивости на месте.
- Прежний вывод игры не изменился — это рефакторинг, поведение то же.

## Подсказки

- `collect::<Vec<_>>()` — «собери в вектор, тип поймёшь сам».
- `filter` оставляет, `map` превращает, `sum`/`count`/`max_by_key` — агрегаторы,
  которые «выжимают» результат.
- `max_by_key` возвращает `Option` — у пустой сумки нет самого тяжёлого предмета.
