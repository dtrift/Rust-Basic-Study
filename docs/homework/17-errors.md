# ДЗ 17. Обработка ошибок. Оператор ?. Обработчики Result, Option

- **Урок:** 17. Обработка ошибок. Оператор ?. Обработчики Result, Option
- **Ветка:** `hw-17-errors`
- **Время:** примерно 1.5 часа

> Перед стартом: `git switch main`, `git pull`, `git switch -c hw-17-errors`.

## Цель

Перестать разбирать ошибки вручную: тип ошибки игры, оператор `?` и понятные
сообщения игроку.

## Легенда

«Не понимаю», «нет такого», «не хватает золота» — игроку нужны человеческие сообщения,
а игре — порядок. Сегодня заводим собственный тип ошибок команды и учимся прокидывать
их наверх оператором `?`, а не разворачивать match на пять экранов.

## Задачи

- [ ] Объяви `enum ParseError { Empty, UnknownCommand(String), NotANumber }` и метод
      `fn message(&self) -> String`: «Введи команду», «Не знаю команду „{0}“»,
      «Номер должен быть числом».
- [ ] `parse_command(input: &str) -> Result<Command, ParseError>`: пустая строка → `Err(Empty)`,
      неизвестная → `Err(UnknownCommand(...))` с текстом команды, остальное как раньше.
      `Take(name)` проверь: имя не пустое.
- [ ] Убеди `main` (или функцию `game_loop`) использовать `?`:
      `fn game_loop() -> Result<(), ParseError>`, внутри — `let cmd = parse_command(&input)?;`.
      При `Quit` возвращай `Ok(())`. В `main` — печать ошибки: `Err(e) => println!("{}", e.message())`
      и игра не завершается (завершай только по Quit). Подсказка: внутренний цикл —
      в функции, которая возвращает `Result`, а наружная перезапускает её при ошибке.
- [ ] Замени ручной разбор номера аптечки на `?`: `n.parse::<usize>().map_err(|_| ParseError::NotANumber)?`.
- [ ] Задокументируй: у `parse_command` — комментарий `/// Разбирает строку игрока в команду.`
      и один doc-тест не обязателен, но приветствуется.
- [ ] * Звёздочка: `fn apply_command(cmd: Command, hero: &mut Hero) -> Result<(), ParseError>`
      — перенос логики match из цикла сюда, цикл становится тонким.

## Самопроверка

- Пустой ввод, « белиберда », «возьми» (без предмета), «использовать аптечку три» — все дают
      свои человеческие сообщения, игра продолжает работать.
- В `game_loop` нет вложенных match на два уровня — `?` сделал работу.
- `cargo test` зелёный: добавь тест `parse_command("") == Err(ParseError::Empty)`.

## Подсказки

- `?` после выражения с `Result` означает: если ошибка — немедленно верни её наверх,
  если успех — достань значение. Ничего тайного здесь нет: это сахар для match.
- `map_err` превращает чужую ошибку (`ParseIntError`) в твою (`ParseError`).
- Сравнить результат с ожиданием в тесте можно через `matches!(parse_command(""), Err(ParseError::Empty))`.
