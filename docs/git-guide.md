# Памятка по git: ветки и Pull Request

Ты уже умеешь делать `git add`, `git commit`, `git push`. Для домашних заданий
понадобятся ещё два навыка: **ветки** и **Pull Request (PR)**. Разберём по шагам.

## Зачем это нужно

- `main` — это всегда работающая версия игры. Она собирается, тесты зелёные.
- Каждое ДЗ делается в отдельной ветке, чтобы `main` не ломался, пока ты экспериментируешь.
- Pull Request — это способ показать наставнику свои изменения и обсудить их до того,
  как они попадут в `main`.

## Жизненный цикл одного ДЗ

```bash
# 1. Обнови main (всегда начинай с этого!)
git switch main
git pull

# 2. Создай ветку для задания (имя ветки написано в задании)
git switch -c hw-05-branches-loops

# 3. Работай. Коммить часто и маленькими шагами
git add src/main.rs
git commit -m "Добавил меню игры"

# 4. Проверь себя перед отправкой
cargo build
cargo test    # если тесты уже есть
cargo fmt

# 5. Отправь ветку на GitHub
git push -u origin hw-05-branches-loops
```

GitHub напечатает ссылку — перейди по ней и открой Pull Request
(кнопка **«Compare & pull request»**). Заполни шаблон и нажми **«Create pull request»**.

## Что происходит дальше

1. Наставник смотрит твой PR: пишет комментарии прямо к строкам кода.
2. Ты отвечаешь: исправляешь, коммитишь в **ту же ветку**, пушаешь — PR обновится сам.

   ```bash
   git switch hw-05-branches-loops
   # ... исправил ...
   git add -A
   git commit -m "Поправил замечание: убрал лишний clone"
   git push
   ```

3. Когда наставник написал «Approved» — PR мёржится (обычно жмёт наставник,
   а ты удаляешь ветку кнопкой **«Delete branch»**).
4. Возвращайся к шагу 1 для следующего ДЗ.

## Частые ситуации

### CI-чек красный

Посмотри лог (клик по красному крестику → Details). Обычно помогает:

```bash
cargo fmt          # если ругается на форматирование
cargo build        # посмотреть ошибку компиляции локально
```

Исправь, закоммить, запушь — чек станет зелёным.

### Нечаянно начал работать в main

```bash
git switch -c hw-05-branches-loops   # ветка заберёт несохранённую работу с собой
```

### Хочу подтянуть свежий main в свою ветку

```bash
git switch main && git pull
git switch hw-05-branches-loops
git rebase main
```

Если `rebase` страшит — просто скажи наставнику, он поможет.

### Как смотреть, что уже в игре

```bash
git log --oneline        # история коммитов
git switch main && cargo run   # запустить последнюю принятую версию
```

## Словарик

| Слово             | Что значит                                                         |
| ----------------- | ------------------------------------------------------------------ |
| ветка (branch)    | отдельная «копия» проекта для твоей работы                         |
| `main`            | главная ветка: всегда работающая версия игры                       |
| Pull Request (PR) | запрос на вливание твоей ветки в `main` + обсуждение с наставником |
| ревью (review)    | наставник читает твой diff и пишет замечания                       |
| merge             | вливание принятой ветки в `main`                                   |
| rebase            | перенос своих коммитов на свежий `main`                            |
| CI                | робот на GitHub: собирает и тестирует каждый PR                    |
